# AGENTS.md

Guidance for AI coding agents working in this repository.

## Project Overview

This is a **university course website template** (content is in Chinese, `zh-CN`). It pairs a static **Astro** course site with **Slidev** slide decks. The design principle is minimal: **authors edit Markdown; everything else is automatic.**

There is no separate syllabus document — the course intro (description, textbook, objectives) lives in the top sections of `lecture01.md`. The site/course name lives in `website/src/config.ts` (`site.title`).

## Content Architecture (how the pieces fit)

1. **`src/`** holds draft content as plain Markdown with **no frontmatter** — the body starts with an H1 (`# 课程标题`).
2. **`website/src/content/`** holds the Astro-consumed Markdown **with YAML frontmatter**. The H1 title becomes the `title` frontmatter field and is **removed from the body**; the rest of the content stays the same.
3. **`slides/`** mirrors lecture content as Slidev slides (`#` = one slide/frontmatter block, `---` separates slides).
4. **`site/`** is a copy of the `website/dist/` build output. Never edit it directly; it is regenerated by `npm run build` in `website/`.

There is **no automated sync script** between `src/`, `website/src/content/`, and `slides/` — propagating content across these is a manual step.

### Lecture Frontmatter Schema (`website/src/content/lectures/*.md`)

```yaml
---
title: string                # required — becomes the page title (was the H1 in src/)
lectureNumber: number        # required — drives homepage ordering + prev/next nav
slidevUrl: string (optional) # online slides; shows a "课件" link on the homepage when set
draft: boolean (default false)
---
```

### Assignment Frontmatter Schema (`website/src/content/assignments/*.md`)

```yaml
---
title: string                 # required
assignmentNumber: number      # required
lectureRef: string            # required — must match a lecture slug, e.g. "lecture01"
submissionFormat: string      # default "学号-HWxx.zip"; hidden in UI if left at the default
downloadFile: string (optional) # e.g. "/assets/hw01.zip"
dueDate: date (optional)
draft: boolean (default false)
---
```

Note: `lectureRef` must match the **lecture slug** (`lecture01`, … `lecture16`), not the title. Assignments have no list page — they're linked from their lecture (homepage + lecture footer).

## Commands

**Full build (from repo root — root `package.json` has no dependencies, just orchestration)**

```bash
npm run build              # build website + slides, mirror into site/
  · scripts/sync-website.mjs → astro build → empty site/ → copy website/dist → restore cached decks
  · scripts/sync-slides.mjs  → build only changed decks → copy each to site/slides/lectureN/
npm run build:website      # astro build + refresh site/ (empty + mirror + restore decks)
npm run build:slides       # incremental: rebuild only changed slide decks, copy to site/slides/lectureN/
npm run build:slides:force # rebuild ALL slide decks
npm run dev:website        # astro dev server
npm run dev:slides         # slidev dev server
npm run dev                # serve the built site/ locally (http://127.0.0.1:4321/course-template/)
npm run serve              # same as dev (alias)
npm run serve -- --port 8080  # serve on a custom port
```

**Website (`website/`)** — for working inside the subproject

```bash
npm install
npm run dev               # start dev server
npm run build             # build static site into dist/
npm run preview           # preview the production build
```

**Slides (`slides/`)**

```bash
npm install
npm run dev               # slidev dev (opens browser)
npm run build             # slidev build → dist/
npm run export            # export to PDF/PNG/PPTX
```

The root build orchestrates both subprojects; it does **not** add root dependencies.

### Build workflow details

- `astro build` **clears `website/dist/` by default** (emptyOutDir in static-build.js), so
  every website build is a full regenerate; `scripts/sync-website.mjs` then empties `site/`
  and mirrors the fresh dist in.
- Slide decks are built **incrementally**: a deck in `slides/dist/lectureN/` is reused (not
  rebuilt) unless `slides/lectureN.md` is newer than its built `index.html`. `--force`
  bypasses this. Shared includes (`pages/`, `snippets/`, `components/`) aren't tracked —
  use `build:slides --force` after changing those.
- Each deck is built with `--base <siteBase>slides/lectureN/ --router-mode hash` so its
  assets resolve under the deployed site path (e.g. `/course-template/slides/lecture01/`);
  `siteBase` is read from `website/astro.config.mjs`. Do **not** pass `--download` — it
  requires Playwright, which isn't installed.
- `site/` = Astro mirror + `site/slides/lectureN/` decks. After a website rebuild the decks
  are restored from the `slides/dist/` cache (cheap copy, no rebuild).
- Astro telemetry is disabled during the build (`ASTRO_TELEMETRY_DISABLED=1`) so it stays
  hermetic.
- `npm run dev` / `npm run serve` (`scripts/serve.mjs`) serves the built `site/` under the
  site `base` (default port 4321; `--port N` or `PORT=N` to change). It redirects `/` to the
  base and falls back to `index.html` for SPA routes, so both the site and the slide decks
  render exactly as deployed. Run `npm run build` first.

## Key Conventions

- **Edit Markdown for all content** (lectures, assignments); the site renders it automatically. UI labels are hardcoded in the Astro templates; `site.title` is the only thing that cannot live in Markdown.
- **No client-side JavaScript** in the website — motion is CSS-only; keep it that way. Respect `prefers-reduced-motion` (nothing auto-animates).
- **Draft filtering**: `draft: true` items are filtered out of the production build (and excluded from prev/next nav).
- **Chinese content**: all site copy and course content is Simplified Chinese (`zh-CN`); keep new content in Chinese.
- **Design language** (see `website/CLAUDE.md` for full detail): scholarly editorial — cool paper background, ink text with green tint, one deep-verdigris accent, system CJK fonts (no external font/JS dependencies). Tailwind v3 with palette in `tailwind.config.mjs`; prose via `.prose-custom` in `global.css`.
- **Layout hierarchy**: `BaseLayout` (HTML shell) → `CourseLayout` (nav + footer) → `DocLayout` (single centered column + inline TOC, h2/h3 only).
- The homepage (`/`) is generated entirely from lecture frontmatter (number, title, slidev link if set, homework link if an assignment references the lecture) — don't hand-write the list.

## Deployment

- **GitHub Pages (primary)**: `.github/workflows/deploy.yml` runs on push to `main` (or
  manually via `workflow_dispatch`). It installs deps (`npm --prefix website ci`, `npm
  --prefix slides ci`), runs the root `npm run build`, adds `site/.nojekyll`, uploads
  `site/` with `actions/upload-pages-artifact@v3`, and deploys with
  `actions/deploy-pages@v4`. Requires Pages source set to **GitHub Actions** in repo
  Settings → Pages (one-time). Netlify support (`netlify.toml`) is kept for fallback.
- **Base path**: `astro.config.mjs` sets `base: '/course-template/'` and `site: 'https://jame-louis.github.io'`. Update the `site` URL before deploying elsewhere. All internal links use `import.meta.env.BASE_URL`.
- Slide deck `base` is derived from `astro.config.mjs` by `scripts/lib.mjs` (`readSiteBase()`), so it stays in sync when you change the site base.
- `site/`, `website/dist/`, `website/.astro/`, `slides/dist/`, and `node_modules/` are build artifacts — don't edit or commit them. A root `.gitignore` covers all of these.

## Getting Started Checklist (for a new course instance)

1. Edit `website/src/config.ts` → `site.title`, `site.term`, `site.description`.
2. Update `site`/`base` in `website/astro.config.mjs` for the target host.
3. Write/edit lectures in `website/src/content/lectures/` (frontmatter + body); intro content goes at the top of `lecture01.md`.
4. Write/edit assignments in `website/src/content/assignments/` with a matching `lectureRef`; drop downloadable files in `website/public/assets/`.
5. Optionally author slide decks in `slides/` and set `slidevUrl` on the lecture.
6. Set `draft: false` on anything ready to publish; build with `npm run build` (root) and preview with `npm --prefix website run preview`.
7. Enable GitHub Pages: repo Settings → Pages → Source **GitHub Actions** (one-time).
   After that, pushing to `main` auto-deploys via `.github/workflows/deploy.yml`.

Use journey/ as the shared project memory across agent sessions.

- Read journey/design.md first at the start of each session. It is the canonical snapshot of the project: current strategy, key design decisions, trade-offs, constraints, and scope.
- Use journey/logs/ for chronological process notes, progress, experiments, and failed paths.
- Use journey/research/ for research notes and background findings.
- Update journey/design.md whenever the effective understanding of the project changes. Do not leave important decisions or trade-offs only in logs.

For any new project, planning-focused request, or sufficiently complex task, start with a fresh plan and write it to journey/plans/YYYY-MM-DD-{title}.md before implementing. Treat files in journey/plans/ as the canonical plans. As work progresses, record concise updates in journey/logs/YYYY-MM-DD-{title}.md using the same date and title convention. In chat, provide only a brief summary and the relevant file path(s).
