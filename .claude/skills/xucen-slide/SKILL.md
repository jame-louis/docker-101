# 许岑 · 电影级幻灯片（xucen-principles）

把幻灯片当成**给看的电影，不是给人读的文档**。讲者是主角；银幕上只放
"镜头"和"台词"，细节在讲者的嘴里（讲者备注）。

先读 `references/principles.md` 拿到完整原则表、镜头类型、密度阈值——这是本技能
唯一的规范出处。**归因红线**：「对比/重复/对齐/亲密」是 Robin Williams 的排版四原则，
不是许岑原创，表述时要分清。

## 两种模式，先分清要干哪件事

- **生成模式（generate）**：吃进逐字稿/要点 → 产出 Slidev markdown。绝大多数情况。
- **审阅模式（audit/design pass）**：对既有内容逐镜打分、标违规、给改法，
  可顺带输出改好的 Slidev。当用户说"审阅/检查/这页好不好/帮我挑毛病"时走这里。

## 生成模式：从稿到片

1. **Speech-First，先有稿**。若只有零散要点，先向用户补齐逐字稿或明确"以要点代稿"。
2. **定画幅与深浅**。预算 16:9（LED 屏偏深色背景，幕布/投影偏浅色），不确定就问。
3. **分镜（Shot List / 三幕剧）**：把稿件抽帧成序列——
   - 片头【空镜】钩子 → 第一幕幕卡【转场】→ 起承 → 高潮 → 片尾【空镜】致谢/彩蛋。
   - 每幕一张幕卡（同构模板），幕内再拆特写镜【特写】。
4. **每镜一句台词**：
   - 标题 = 一句话台词，不是名词标签（❌"系统安全" → ✅"每一层都安全，不等于整体安全"）。
   - 银幕 ≤ 1 句台词 + ≤3 个要点；关键字**只加粗一次**。
   - 细节、完整句、数据解释全部下放到讲者备注——**永不丢失内容**。
5. **补镜头语言**：数据/案例尽量给"图片即镜头"（全出血或 `image-right` + 一句图注）；
   逐条揭示用 `v-clicks`；幕卡淡入给"摄像机"连续感。
6. **写讲者备注**：每镜 `<!-- 讲者备注：【镜头类型】+ 细节 + 教学提示 -->`。
7. **验证**：`python3 scripts/audit-shots.py <file>.md`，若有 DENSE → 把超长那镜的
   可见面精简、细节沉到备注，重跑至全绿。

## 审阅模式：逐镜 design pass

对每一镜，对照 `references/principles.md` 逐项给 **结论 + 证据 + 改法**：

- 台词式标题：是句子还是名词标签？
- 留白 / 密度：跑 `scripts/audit-shots.py`，DENSE 镜 → 指出要下放的细节。
- 银幕不重复口播：银幕上是否有本该在嘴里念的完整句？
- 一致性与完整性：幕卡是否同构？粗体是否只在关键词加了一次？样式是否统一？
- 次序：有没有序号/时间线/递进制造悬念？
- 图片即镜头：图片是不是大镜头 + 一句图注？
- 讲者备注：每镜有没有备注？被删内容有没有丢？（永不丢失内容）

输出：**逐镜审阅表**（各原则 pass/fail + 一句话证据 + 具体改法）。若用户要成品，
再按审阅产出改好的 Slidev markdown。

## 密度规则（审计依据）

- 可见文字（去掉讲者备注、HTML 注释、图片行后）≤ ~6 行 **且** ≤ ~200 字符。
- 超过即为 DENSE → 下放备注。
- 例外（本身是"镜头"，可超长）：`>` 引用、表格行、LaTeX 公式、代码块、一句图注。

## Slidev 成品模板约定

```markdown
---
theme: seriph
transition: fade          # 幕卡可用 fade;内容推移可选 slide
---

<!-- 片头 · 空镜 -->
# 一句话钩子(一张图更好)

---

## 第一幕 · 万物相连      # 幕卡(同构模板)

<!-- 转场 -->

---

# 每一层都安全，不等于整体安全       # 台词式标题

- 防线①→⑤               # 编号制造次序
- 第二点
- <v-clicks>第三点逐条出现</v-clicks>

<!-- 讲者备注：【特写】单点深入。细节句A; 细节句B; 教学提示:先用防线比喻建立理解再引入整体性。 -->

---

# 结尾致谢

<!-- 空镜 -->
```

## 交付清单（生成模式收尾自检）

- [ ] 有片头【空镜】、三幕幕卡【转场】、片尾【空镜】，全片同一部电影
- [ ] 每镜标题是"一句话台词"，不是名词标签
- [ ] 每镜 ≤6 行 / ≤200 字，`audit-shots.py` 无 DENSE
- [ ] 每镜有 `<!-- 讲者备注 -->`，注明【镜头类型】
- [ ] 删下的每个细节都能在备注找到（没有丢失内容）
- [ ] 图片即镜头：需要处给了全出血 / `image-right` + 一句图注
- [ ] 关键处用了 `v-clicks` / 递进 / 编号来制造节奏（不是处处都有）
- [ ] 未把"对比/重复/对齐/亲密"误记为许岑原创

## 例外与边界

- 演讲稿先行是规范流程；"边讲边做 PPT"是罗永浩锤子发布会的赶工轶事，**不是**推荐流程。
- LaTeX 公式、代码演示、数据表格允许超长——它们是"镜头"，不是冗余，不要为凑密度删掉。
- 若用户坚持塞更多文字进银幕（信息型文档式幻灯片），说明取舍，但仍尊重其最终决定。
