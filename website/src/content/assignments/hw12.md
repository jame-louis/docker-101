## 作业目标

在案例一的基础上，**独立编写**一个给"静态网站"用的 **Dockerfile**，构建成镜像并运行测试，最后通过 bind mount 修改网站内容并重新验证——把 Dockerfile 编写、构建、运行与挂载这条链路独立走通。

## 作业要求

### 实战：自写 Dockerfile 部署并测试你的静态网站

**第 1 步：准备你自己的网站**

```bash
mkdir -p site
echo '<h1>My Own Site v1</h1>' > site/index.html
```

**第 2 步：独立编写 Dockerfile（不照抄，核心指令应含 `FROM`、`COPY`、`EXPOSE`）**

```dockerfile
FROM nginx:alpine
COPY site/ /usr/share/nginx/html/
EXPOSE 80
```

**第 3 步：构建并运行测试**

```bash
docker build -t my-site .
docker run -d --name ms -p 8080:80 my-site
curl http://localhost:8080        # 显示 My Own Site v1
docker logs ms
```

**第 4 步：用 bind mount 改内容再测**

```bash
echo '<h1>My Own Site v2</h1>' > site/index.html
docker rm -f ms
docker run -d --name ms -p 8080:80 -v "$PWD/site":/usr/share/nginx/html my-site
curl http://localhost:8080        # 显示 v2, 无需重建镜像
```

## 知识拓展（文字回答）

1. `COPY site/ /usr/share/nginx/html/` 这条指令在做什么？如果把目标目录 `target` 写错，`docker build` 会怎样报错？
2. `EXPOSE 80` 声明了端口，为什么**还是**需要 `docker run -p 8080:80`？两者区别是什么？（提示：EXPOSE 只是"说明"，-p 才是真的"映射"。）
3. 用 bind mount 改内容时没有重新 `docker build`，为什么浏览器立刻能看到新内容？
