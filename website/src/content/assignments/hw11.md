## 作业目标

获取 **Redis** 镜像，部署一个**带持久化数据卷**的 Redis 容器，通过 `docker exec` 进入容器终端界面，用 `redis-cli` 连接并完成读写验证，理解数据库作为"有状态服务"必须持久化的原因。

## 作业要求

### 实战：部署并连接 Redis

**第 1 步：拉取镜像并启动（含持久化与密码）**

```bash
docker pull redis:7
docker run -d --name my-redis \
  -p 6379:6379 \
  -v redisdata:/data \
  redis:7 --requirepass mypass --appendonly yes
docker ps        # 确认 Up
```

**第 2 步：进入容器终端连接并进行验证**

```bash
docker exec -it my-redis redis-cli -a mypass
```

在 `redis-cli` 交互终端里输入：

```
127.0.0.1:6379> PING        # 期望返回 PONG
127.0.0.1:6379> SET city beijing
OK
127.0.0.1:6379> GET city    # 期望返回 "beijing"
127.0.0.1:6379> exit
```

**第 3 步（加分/进阶）：验证数据不随容器删除而丢失**

```bash
docker rm -f my-redis
docker run -d --name my-redis -p 6379:6379 \
  -v redisdata:/data redis:7 --requirepass mypass --appendonly yes
docker exec -it my-redis redis-cli -a mypass GET city   # 还应是 "beijing"
```

## 提交内容

1. `docker pull redis:7` 与 `docker run ...` 之后 `docker ps` 显示 `my-redis` 为 `Up` 的截图；

3. （进阶）上述第 3 步删容器重建后仍能 `GET city` 返回 `"beijing"` 的截图；
4. 一个简短的文字回答：既然容器可写层会随容器删除而消失，为什么删掉 Redis 容器后数据还在？数据卷在这中间起了什么作用？
